# Prompt Antigravity - Site web KA Taxi Paris

Tu dois concevoir un site web premium, moderne, fluide, credible et oriente conversion pour une societe de transport nommee KA Taxi, specialisee dans les transferts aeroportuaires a Paris.

Lis tout ce document avant de commencer. Tu dois appliquer chaque instruction strictement, sans simplifier le besoin, sans ignorer les contraintes metier, sans negliger la securite, sans livrer un simple mockup visuel. L'objectif est de produire un vrai site professionnel inspire de standards haut de gamme, pret a recevoir de vraies demandes de reservation.

## 1. Objectif general

Le site doit permettre a un visiteur de comprendre immediatement que KA Taxi propose des transferts depuis et vers les aeroports de Paris.

Le site doit transmettre une image de fiabilite, de ponctualite, de confort, de discretion et de serieux.

Le site doit permettre de remplir un formulaire de reservation unique integre dans une page longue.

Le site doit envoyer la demande sans faire quitter le visiteur du site.

Le site doit afficher ensuite un message de confirmation clair indiquant que la demande a bien ete recue et qu'un appel telephonique sera effectue pour confirmer la reservation.

## 2. Modele metier a respecter absolument

Respecte strictement les points suivants :

- aucun prix affiche sur le site ;
- aucun paiement en ligne ;
- aucun devis instantane ;
- aucune ouverture de WhatsApp ;
- aucune redirection vers une messagerie externe pour terminer la reservation ;
- la reservation est une demande envoyee a l'entreprise ;
- la confirmation finale se fait ensuite par telephone ;
- le site doit paraitre professionnel, premium et credible.

## 3. Positionnement de la marque

Le site doit communiquer les idees suivantes :

- transport aeroportuaire a Paris ;
- service type G7 ;
- reservation simple ;
- prise en compte des bagages ;
- confirmation humaine par appel ;
- experience serieuse et rassurante.

Important :

- il est permis de mentionner service type G7 ou une formulation proche ;
- il est interdit de laisser croire que KA Taxi est officiellement G7 si cela n'est pas vrai ;
- il est interdit de suggerer une affiliation officielle non confirmee.

## 4. Langues du site

Le site doit etre bilingue :

- francais par defaut ;
- anglais disponible en seconde langue.

Exigences :

- toutes les sections doivent exister dans les deux langues ;
- la navigation, les boutons, les labels, les messages d'erreur, les messages de succes et le footer doivent etre traduits ;
- le ton francais doit sembler naturel, local et credible pour Paris ;
- l'anglais doit etre simple, propre et comprensible pour une clientele internationale.

## 5. Structure obligatoire de la page

Le site doit etre une longue page avec navigation fluide. La structure conseillee est la suivante.

### 5.1 Header

Le header doit contenir :

- logo KA Taxi ;
- menu avec ancres vers les sections ;
- bouton principal de reservation ;
- selecteur de langue ;
- design propre et premium ;
- excellente lisibilite sur mobile et desktop.

### 5.2 Hero

Le hero doit permettre de comprendre le service en moins de 3 secondes.

Il doit inclure :

- un titre fort, clair et premium ;
- un texte court expliquant le service ;
- un bouton principal menant au formulaire ;
- une composition visuelle elegante liee a Paris, aux aeroports, a la mobilite premium et a la fiabilite.

Le hero doit faire comprendre immediatement :

- transferts aeroportuaires a Paris ;
- reservation simple ;
- confirmation par telephone ;
- service type G7.

### 5.3 Presentation du service

Cette section doit expliquer brievement :

- ce que fait KA Taxi ;
- pour qui le service est concu ;
- comment fonctionne la demande de reservation ;
- pourquoi l'utilisateur doit se sentir en confiance.

### 5.4 Aeroports desservis

Prevoir un bloc dedie aux aeroports principaux :

- Charles de Gaulle CDG ;
- Orly ORY ;
- Beauvais BVA.

Pour chaque aeroport, montrer clairement que KA Taxi assure les trajets depuis et vers cet aeroport.

Cette section doit renforcer la perception de specialisation et de couverture claire.

### 5.5 Pourquoi choisir KA Taxi

Prevoir 4 a 6 raisons maximum, fortes et credibles, par exemple :

- reservation simple et rapide ;
- service type G7 ;
- ponctualite ;
- confort ;
- prise en compte des bagages ;
- confirmation rapide par appel.

Interdictions :

- ne pas utiliser de promesses vagues ;
- ne pas copier des slogans generiques de startup ;
- ne pas afficher des cartes de fonctionnalites sans ame.

### 5.6 Comment ca marche

Cette section doit expliquer le processus reel :

1. le client remplit la demande ;
2. KA Taxi recoit la demande ;
3. le client est recontacte par telephone ;
4. la reservation est confirmee ensuite.

Cette section est essentielle car il n'y a ni prix affiche ni paiement en ligne.

### 5.7 Formulaire de reservation

Le formulaire est l'element le plus important du site.

Il doit etre integre directement dans la page longue, etre lisible, rassurant, moderne et facile a utiliser sur mobile.

Champs recommandes :

- nom complet ;
- telephone ;
- email facultatif ou recommande selon la logique UX retenue ;
- type de trajet : vers l'aeroport, depuis l'aeroport, aller-retour ;
- aeroport ;
- date ;
- heure ;
- adresse de depart ou d'arrivee ;
- nombre de passagers ;
- nombre de bagages ;
- bagages speciaux ou remarques ;
- message complementaire.

Le formulaire doit inclure un texte rassurant qui explique que :

- la demande n'est pas une confirmation instantanee ;
- l'equipe recontactera le client ;
- aucune transaction en ligne n'est effectuee a cette etape.

### 5.8 Message de succes

Apres soumission valide :

- ne pas rediriger brutalement l'utilisateur ;
- afficher un message de succes elegant ;
- rassurer sur la suite ;
- rappeler qu'un appel de confirmation sera effectue.

### 5.9 Footer

Le footer doit rester propre et sobre.

Il peut contenir :

- nom de la societe ;
- rappel du service ;
- telephone ;
- liens internes ;
- rappel linguistique ;
- eventuelle mention de confidentialite.

## 6. Direction artistique exigee

Le rendu doit etre premium, contemporain, sobre, fluide et credible.

Il faut eviter absolument :

- l'apparence template generique ;
- l'esthetique startup SaaS sans personnalite ;
- les gradients violets ou bleus stereotypes ;
- les blocs repetitifs et sans ame ;
- les effets visuels gratuits qui nuisent a la confiance.

Direction conseillee :

- palette sombre elegante ou neutre haut de gamme ;
- accents or, champagne, ivoire, beige premium ou vert profond tres maitrise ;
- typographie claire, lisible et raffinee ;
- visuels associes a Paris, aux aeroports, a la mobilite premium et au service professionnel.

## 7. Animation et interactivite

Le site doit etre anime et interactif, mais avec retenue.

Tu dois integrer :

- animations d'apparition au scroll ;
- transitions douces ;
- reponses fines sur hover et focus ;
- interactions premium sur les boutons, cartes et champs ;
- sensation generale de site vivant et soigne.

Interdictions :

- animations gadgets ;
- surcharges visuelles ;
- lenteurs artificielles ;
- effets cheap ;
- comportements qui distraient de la reservation.

Principe : raffinement, pas spectacle inutile.

## 8. Experience mobile

Le site doit etre pense mobile-first.

Exigences :

- adaptation parfaite sur smartphone ;
- aucun debordement horizontal ;
- hero lisible ;
- sections bien espacees ;
- boutons confortables ;
- formulaire facile a remplir au pouce ;
- qualite visuelle elevee sur petit ecran.

Le rendu desktop doit etre egalement excellent.

## 9. Logique d'envoi des reservations

Le site ne doit jamais ouvrir WhatsApp.

Le site ne doit pas dependre d'un numero WhatsApp Business.

La demande doit etre envoyee de maniere professionnelle en arriere-plan.

Orientation recommandee :

- endpoint backend ;
- function serverless ;
- relais securise ;
- envoi vers Telegram si cette solution est retenue.

Regles absolues :

- ne jamais exposer un secret cote client ;
- ne jamais exposer un token dans le front-end ;
- ne jamais publier une cle sensible dans le JavaScript ;
- valider et nettoyer les donnees ;
- proteger l'envoi contre l'abus.

Si Telegram est utilise :

- integrer Telegram cote serveur ;
- proteger les secrets ;
- formatter les messages de reservation de facon claire pour l'operateur.

## 10. Securite et protection obligatoires

Tu dois integrer une vraie couche de securite adaptee a un site de reservation.

Minimum obligatoire :

- validation cote client ;
- validation cote serveur ;
- sanitation des entrees ;
- protection anti-spam ;
- protection contre les soumissions abusives ;
- limitation de debit si possible ;
- gestion securisee des secrets ;
- messages d'erreur non verbeux ;
- protection contre les injections simples ;
- headers de securite lorsque c'est applicable ;
- politique de confidentialite minimale si des donnees personnelles sont traitees.

Protection additionnelle recommandee :

- champ honeypot ;
- delai minimal avant soumission ;
- filtrage de longueur ;
- validation du telephone ;
- validation des dates et heures ;
- normalisation des donnees ;
- blocage de motifs manifestement malveillants ;
- CSRF si l'architecture le necessite.

Verifier aussi :

- aucune cle API visible ;
- aucune donnee sensible dans le HTML public ;
- aucune dependance inutilement risquee ;
- aucune surface d'attaque evidente creee par les scripts ou animations.

## 11. Ton redactionnel

Le contenu doit etre :

- premium ;
- rassurant ;
- clair ;
- sobre ;
- credible ;
- oriente conversion.

A eviter :

- slogans generiques ;
- phrases trop publicitaires ;
- promesses impossibles ;
- formulations maladroites ;
- repetitions inutiles.

Le ton doit inspirer :

- professionnalisme ;
- fiabilite ;
- disponibilite ;
- simplicite du parcours.

## 12. Exigences UX prioritaires

Le site doit reduire les hesitations dues a l'absence de prix publics.

Pour cela il doit :

- expliquer clairement le fonctionnement ;
- rassurer sur la suite du processus ;
- montrer qu'une equipe prendra contact ;
- inspirer confiance par sa qualite visuelle ;
- limiter toute friction dans le formulaire.

Le CTA principal doit etre tres clair.
La hierarchie visuelle doit mener naturellement vers la reservation.

## 13. Ce qu'il ne faut surtout pas faire

- ne pas afficher de prix ;
- ne pas proposer de paiement en ligne ;
- ne pas ouvrir WhatsApp ;
- ne pas envoyer l'utilisateur vers une application externe ;
- ne pas livrer un site banal ;
- ne pas produire une esthetique IA generique ;
- ne pas oublier la version anglaise ;
- ne pas negliger le mobile ;
- ne pas exposer de secrets ;
- ne pas revendiquer une affiliation officielle a G7 sans base reelle.
